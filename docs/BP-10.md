# BP-10 implementation notes

## Configuration and balancing

`apps/shared/src/config/weapons.ts` remains the gameplay source of truth. Each
entry describes one named weapon, with a stable network/equipment `id` and a
separate `category`. The existing IDs (`rifle`, `smg`, `shotgun`, `sniper`) are
preserved for saves, bindings, models and private-room rules. Category does not
choose damage, recoil, spread or fire rate. Another weapon in the same category
can have a different configuration; adding an equipable ID also requires adding
its inventory/model/binding entries, as before.

`WeaponConfig` now requires `category`, eleven `bodyMultipliers`, and a
`damageFalloff` array of `{ distance, multiplier }` points. Existing actual
values remain authoritative: `fireInterval` controls firing, `damage` is base
damage per bullet/pellet, recoil fields control handling, spread fields control
accuracy, and `adsTime` controls the ADS transition. `range` is maximum bullet
travel, separate from full-damage range. World units are meters.

| Weapon        | RPM |               Base damage | Full damage | Maximum travel |    ADS |
| ------------- | --: | ------------------------: | ----------: | -------------: | -----: |
| AR-01 rifle   | 600 |                        25 |        25 m |           80 m | 140 ms |
| SM-02 SMG     | 900 |                        17 |        12 m |           65 m | 100 ms |
| SG-03 shotgun |  75 | 12 per pellet, 15 pellets |         8 m |           45 m | 180 ms |
| SR-04 sniper  |  45 |                        90 |        25 m |          220 m | 315 ms |

| Region     | Rifle |  SMG | Shotgun | Sniper |
| ---------- | ----: | ---: | ------: | -----: |
| Head       |   1.8 |  1.8 |     1.5 |    1.5 |
| Upper body |     1 |    1 |       1 | 100/90 |
| Lower body |   0.9 | 0.95 |       1 |    0.9 |
| Each arm   |  0.85 |  0.9 |     0.9 |    0.7 |
| Each hand  |  0.75 |  0.8 |    0.85 |    0.7 |
| Each leg   |   0.8 | 0.85 |     0.9 |    0.7 |
| Each foot  |   0.7 | 0.75 |     0.8 |    0.7 |

Left and right limbs have independent configuration keys, even where initial
balance values match. The sniper base damage was reduced to 90 in the follow-up:
close-range head hits deal 135, upper body 100, lower body 81, and limbs 63 before
remaining-health clamping. The ticket's illustrative 1.25 head multiplier is
covered separately by the exact 101.25 damage calculation test.

The sniper upper-body multiplier is 100/90. This keeps its base damage at 90
while producing 100 upper-body damage through 25 m, 95 at 37.5 m and 90 at 50 m.
The existing curve then produces 80 at 75 m, 70 at 100 m and 60 from 125 m onward.

Falloff points, written as `meters: multiplier`:

- Rifle: `0:1, 25:1, 50:0.8, 80:0.65`.
- SMG: `0:1, 12:1, 25:0.8, 45:0.6, 65:0.45`.
- Shotgun: `0:1, 8:1, 15:0.7, 25:0.4, 45:0.15`.
- Sniper: `0:1, 25:1, 50:0.9, 75:0.8, 100:0.7, 125:0.6`.

`weapons/statistics.ts` derives the six display ratings from these actual values;
there is no second collection of weapon stats. Ratings are rounded and clamped
to 0-100. Fire rate uses RPM/10; damage uses base damage; range uses full-damage
meters/1.25; control uses `100 / (1 + 10 * recoilKick / recoilRecovery)`, where
recoilKick is the magnitude of the pitch/yaw impulse; accuracy uses
`100 / (1 + 2 * adsSpread)`; ADS uses `100 * (1 - adsTime / 0.5)`.
These are comparison scales, not inputs to gunplay. Raw values and units appear
below each bar. Recoil, spread, fire rate and ADS timing were not retuned.

## Shared body rig and collision

`combat/avatar.ts` now defines eleven dedicated boxes with explicit `region`
metadata: head, upper/lower torso, left/right arm, hand, leg and foot. The gun
remains a cosmetic part and never absorbs bullets. The existing torso and limb
volumes were split instead of adding a second, unrelated collision character.
Feet extend slightly forward to match their visible shape.

The rig uses local joint pivots. Hands share their shoulder's rotation and feet
share their hip's rotation. `avatarPartPose` evaluates the same transforms for
the client instanced mesh and the server ray tests. Root yaw, head pitch,
vertical posture scaling and world position apply to all relevant parts.
There is no world-height heuristic to decide which region was hit.

The server advances gait phase from movement speed and blends gait amplitude
while walking/sprinting. Jumping and low postures blend out the gait while the
rig continues following actual movement and capsule height. Colyseus publishes
`gaitPhase` and `gaitAmount`; remote interpolation blends them, including cycle
wraparound. Both fields are server-owned and reset on respawn. The current game
has no separate crouch input; existing sliding, backsliding, diving and recovery
heights use the same transforms.

`intersectAvatar` transforms the ray into the root and joint spaces, tests each
body box, and returns the closest region plus its world hit point and distance.
Rendering stays in one instanced mesh for up to eight avatars: twelve rendered
parts per avatar, eleven of which are damageable. The expanded rig adds no
per-region draw calls. Training uses eleven Rapier sensor boxes and the same
body geometry, scaled to the existing hologram's height. Its movement course
remains passable, and all sensors disable/re-enable together on defeat/reset.

## Damage and server validation

`combat/damage.ts` centralizes:

```text
damage = weapon.damage * weapon.bodyMultipliers[region] * rangeMultiplier
t = (hitMeters - lower.distance) / (upper.distance - lower.distance)
rangeMultiplier = lower.multiplier + (upper.multiplier - lower.multiplier) * t
```

The first and last multipliers clamp their respective ends of the curve.
An empty profile explicitly disables falloff. Profiles start at zero and have
strictly ascending distances; configuration tests check this. Distances outside
maximum bullet travel, negative/non-finite distances and unknown regions return
zero damage. Internal health and confirmed damage remain fractional. HUD text
alone rounds damage and health for readability.

Both `PracticeCombat` and `ServerCombat` call this helper once per pellet that
actually hits. Distance is the three-dimensional distance from the actual
shooter eye to the resolved surface hit point, not the target's center.
Shotgun damage aggregates all valid pellets and applies one health change and
one damage sequence increment per target per shot. Feedback caps damage to the
target's remaining health without changing the underlying damage formula.

Multiplayer continues accepting only validated movement/look/button intent.
The room identifies the shooter from its connection; the server chooses the
owned weapon, enforces shared ammo/reload/bolt/fire-rate rules, generates spread,
clips against Rapier world cover and finds the closest living character region.
It reads all multipliers and profiles from its own configuration. Client hit
regions, hit positions, target IDs, damage, distances, multipliers, profiles and
gait claims are not accepted as shot results. Existing friendly-body blocking,
TDM friendly-fire prevention, spawn protection, kills and respawns are preserved.
Private-room weapon restrictions still use the same server ownership sets.

## Weapon information interface

Open **ARMORY** in the main/pause menu. It initially shows the equipped weapon;
inspection buttons switch the six statistics without changing equipment.
Restricted rooms display only allowed weapons. Expand **BODY MULTIPLIERS & RANGE
PROFILE** for all eleven body multipliers, range points and maximum bullet
travel. The panel uses the existing tactical dialog, focus restoration,
keyboard dismissal, shared scrollbar and responsive layout. Statistics are
rendered only while this panel is open, adding no always-visible combat HUD.

## Validation

Automated tests: 406 passed across 46 files. Includes all eleven regions on all
weapons, curve breakpoints/midpoints/continuity, asymmetric limb multipliers,
explicit no-falloff profiles, invalid distance/region handling, exact fractional
damage, training sensors/falloff, transformed animated hitboxes matching actual
rendered instance matrices, server-owned gait/respawn, all weapon server damage,
pellet aggregation, fire-rate/ownership restrictions, FFA/TDM and reload/ADS
regressions. `npm run build` (including typecheck) and `npm run lint` pass.

Chrome: 28 original BP-10 scenarios passed, covering the new Armory, all six
configuration-derived values, eleven body multipliers, private-room filtering,
focus/keyboard behavior, 960x640 and 390x844 layouts, existing settings, sights,
firing, reload interruption, sniper scope/bolt timing, sensitivity, sprint carry,
private capacities/loadouts and server-confirmed hits/kills/respawns. The sniper
pixel-read helper issue was corrected and all four sniper scenarios rerun green.
No production changes were needed for that test issue.

The sniper follow-up reruns all eight current sniper browser scenarios, including
four new real scoped shots at the training target's left/right arms and legs.
Each limb hit registers 63 damage, leaving 37 health. Actual eye-to-target firing
tests also cover all eleven training regions, and server sniper cases explicitly
verify both arms and legs at the new damage. The reported zero-damage symptom
was not reproduced in the current build. A separate floating-point display issue
was corrected: 37.00000000000001 health now displays as 37 rather than 38, without
rounding internal damage. Restart the room server and refresh the browser to load
the current configurations and hitboxes.
