# BP-13 — cross-platform controls

BREAKPOINT now supports keyboard/mouse and a landscape touchscreen HUD through
the existing movement, weapon and authoritative multiplayer systems.

## Behavior

- Device detection combines touch points, primary/available pointer capabilities,
  hover, viewport dimensions and screen dimensions. UA/platform checks supplement
  phone and desktop-identity iPad identification. Touchscreen laptops default to
  keyboard/mouse. A menu tap selects touch; a mouse click selects mouse capture.
- Phones/tablets must be landscape in the lobby and gameplay. Portrait opens a
  fullscreen native modal above existing room/settings dialogs, prevents Escape
  dismissal and refuses gameplay entry. Rotating sideways removes it automatically.
  Rotating during play clears input and pauses locally; resume explicitly afterward.
- Startup attempts a landscape lock. Explicit handheld entry or **Enable Landscape**
  can request fullscreen and retry locking. Unsupported/rejected APIs leave the
  rotate instruction available. Desktop/hybrid users are never forced fullscreen.
- Left joystick supplies analog movement with a radial dead zone. The right area
  supplies relative camera deltas. Sprint/ADS toggle; Fire/Jump hold; Slide, Dive,
  Reload, Swap, Scores and Pause trigger existing actions. Swap respects room weapon
  restrictions. Tablet controls are larger and more widely spaced.
- Pointer IDs own controls independently, including separate joystick and look
  owners. Movement + look + ADS + fire work together. Capture, pointer cancellation,
  lost capture, blur, hidden tabs, death, portrait rotation, room exit and results
  clear the applicable intentions. Pause cannot click a menu button beneath the
  removed HUD. New gestures establish a fresh look origin.
- Settings → Sensitivity → **Touch Camera** contains independent general, ADS and
  sniper values (1–300, default 100). ADS uses the weapon's existing blend
  and FOV scaling. Invert Y applies to touch too. Settings persist in the existing
  storage object; old mouse settings migrate unchanged. Reset Touch Sensitivity
  affects only the three touch values. The **Gyroscope** group provides an
  optional motion input with Off, ADS-only and Always-on modes, independent
  horizontal and vertical inversion, and reference, measured and legacy gains.
  It maps sensor rates to the display's pitch axis and a gravity-informed
  yaw axis perpendicular to it. Each valid sample is integrated once.
  [The gyro settings walkthrough](../README.md#mobile-and-tablet-controls-bp-13) covers
  collecting measurements and entering a calibration profile.

Browsers control orientation-lock availability and may require fullscreen or a
user gesture. The viewport blocker remains the reliable fallback; a website
cannot override a device's rotation preference. See the
[Screen Orientation specification](https://www.w3.org/TR/screen-orientation/).

## Files and integration

| Files                                                                        | Responsibility                                                                                 |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `game/input/InputManager.ts`, `InputController.ts`                           | Combine intentions, session/capture lifecycle, compatibility export, control click suppression |
| `KeyboardInput.ts`, `MouseInput.ts`                                          | Existing bindings, held actions, mouse look and sensitivity                                    |
| `TouchInput.ts`, `VirtualJoystick.ts`, `TouchCamera.ts`                      | Native multitouch handlers, analog joystick and relative look                                  |
| `deviceCapabilities.ts`                                                      | Capability classification, orientation/fullscreen fallback                                     |
| `components/MobileHUD.tsx`, `app/mobile.css`                                 | Phone/tablet controls, safe areas, compact combat HUD and landscape menus                      |
| `components/OrientationOverlay.tsx`                                          | Capability updates and portrait modal                                                          |
| `app/App.tsx`, `game/core/Game.ts`                                           | Mode selection, HUD attachment, landscape entry guards and pause cleanup                       |
| `game/settings/userSettings.ts`, `components/SettingsPanel.tsx`              | Persistent touch sensitivities and sliders                                                     |
| `CommandMenu.tsx`, `MatchHud.tsx`, `main.tsx`, `index.html`                  | Touch instructions, stylesheet loading and safe-area viewport                                  |
| `MobileInput.test.ts`, `tests/browser/mobile.spec.ts`, `sensitivity.spec.ts` | Touch/capability tests and browser regression coverage                                         |

Client source paths are relative to `apps/client/src` unless otherwise specified.
Movement physics, recoil, damage, weapon timing, networking messages, server hit
validation, rendering targets, texture filtering and pixel resolution are unchanged.
No dependencies or downloaded assets were added.

High-frequency touch movement updates native intention objects and the joystick
knob directly. Controls cache DOM references; look gestures do not query layout.
No React state update is scheduled by pointermove. Existing telemetry still updates
the React HUD at 4 Hz. Touch camera scaling reads CSS viewport dimensions, retaining
consistent turning across different phone/tablet sizes.

## Validation

- 453 tests across 53 files pass, including the existing desktop sensitivity and
  binding tests plus new device classification, settings migration, multitouch,
  pointer cancellation, analog dead zone, hybrid input and click-through coverage.
- Production build/typecheck, ESLint and whitespace checks pass.
- A live multiplayer touch run on the development machine measured 59.86 FPS,
  16.71 ms mean frame time, 1.91 ms CPU submission and 12 draw calls. These are
  Chrome emulation results on the host GPU, not measurements from mobile hardware.
- 24 distinct Chrome browser scenarios pass across the regression and final mobile
  runs: five mobile/tablet/hybrid scenarios and nineteen
  desktop scenarios for pointer capture, collision, slide/jump/dive, reload and
  ADS cancellation, persisted sensitivity, real server look data, countdown audio,
  frozen early input, host/guest automatic entry and capture-denial recovery.
- The 640×360 layout check confirms every action button is at least 44×44 CSS pixels,
  stays within the viewport and does not overlap another action button. The portrait
  blocker remains above an open native room dialog. Screenshots include `test-results/bp13-portrait.png`,
  `bp13-phone-lobby.png`, `bp13-phone-gameplay.png`, `bp13-tablet-sniper.png` and
  `bp13-small-phone.png`.

Chrome's Android-style touch profile and desktop-identity iPad profile run on the
development machine's GPU. CDP supplies real simultaneous touch streams. This
verifies browser behavior and synchronization, not physical Android/iOS performance
or Safari certification. WebKit and physical mobile devices were unavailable here.
Before release, perform the hardware checks below on Android Chrome, iPhone Safari
and iPad Safari, including device rotation, app switching, safe-area insets, sound,
thermal behavior and sustained multiplayer performance.

## Test on a physical phone or tablet

For an already deployed build, use its frontend HTTPS URL and turn the device
sideways. Both the frontend and configured room-server URL must be reachable from
the device. `localhost` on a phone refers to the phone itself.

For development on the same Wi-Fi network, replace `192.168.1.50` below with your
PC's IPv4 address from `ipconfig`. These are terminal environment variables; the
server does not automatically load `.env` files.

Terminal 1 — room server:

```powershell
$env:HOST='0.0.0.0'
$env:ALLOWED_ORIGINS='http://192.168.1.50:5173'
npm.cmd run dev:server
```

Terminal 2 — frontend:

```powershell
$env:VITE_SERVER_URL='http://192.168.1.50:2567'
npm.cmd run dev --workspace=@breakpoint/client -- --host 0.0.0.0 --port 5173 --strictPort
```

Open `http://192.168.1.50:5173` on the device. Allow the local server through the
PC's private-network firewall if needed. LAN HTTP can reject orientation/fullscreen
APIs; manual rotation still works. Use HTTPS for public hosting.

1. Open in portrait: the instruction covers the lobby and Escape does not dismiss
   it. Rotate while a room dialog is open; that dialog must stay below the rotation
   instruction and gameplay cannot start in portrait.
2. Rotate sideways and enter training. Hold joystick + drag right + toggle ADS +
   hold Fire. Releasing one finger must preserve the other controls.
3. Toggle Sprint, move forward, tap Slide and Jump, then try Dive. Exercise existing
   slide cancellation, wall jumps and momentum without changing the desktop rules.
4. Swap through all weapons. Check sniper scope styles, reload, fresh ADS cancelling
   partial reloads, and scoped look sensitivity. Change touch sliders, reload the
   page and verify persistence and separate reset behavior.
5. Hold movement/fire, rotate to portrait or switch apps. Return and resume: no
   stuck movement, firing, ADS or camera jump. Pause must open the menu without
   opening Private Rooms. On a touchscreen laptop, resume once by touch and once
   by mouse; keyboard controls must still work.
6. Create a private room from the phone, join from a second browser, ready up and
   start. Both should enter 3-2-1 automatically, freeze until GO and synchronize
   movement, shooting, damage, scores and respawns. Try a restricted weapon room.
7. Use Performance/adaptive graphics initially and run several minutes on each
   physical device. Record FPS, frame time, input response, heat and battery use;
   compare higher presets only after the baseline is stable.
